### SQL-to-CSV preparation and dashboard design

Phase 5 consumes the validated SQL database and Phase 4 definitions. The active Luke contract exports UTF-8 aggregate metric slices with stable headers/keys, numerator/denominator fields, fractional rates, documented nulls, geography precision and source/rule versions. The older ISO-date/USD-pay wording is superseded: no salary amounts/currencies, posting/hiring time series or arrangement shares are exported. Annual-field coverage is separately labeled. Record SQL query/version, reporting window, export timestamp, row count and source snapshot in an export manifest. Validate unique keys, missing/invalid values and totals before import. The exports, manifest and SQL/CSV controls now exist; native Tableau matching remains pending. See the [export dictionary](phase5_export_dictionary.md).

The active design coordinates role counts/shares, inherited skill-tag frequencies/conditional percentages, city/county/community associations, explicit seniority, data coverage and global classification limitations. It includes no salary amount/comparison view. A ranked association chart avoids geocoding ambiguous community labels. Label city counts non-additive and retain county-only/unknown geography diagnostics. Filters may include role, city, explicit seniority, arrangement and reporting window only when supported by the data and exported grain. Cross-filter actions and reset controls must preserve the KPI definitions.

Use separate worksheets/panel categories in one SQL-generated metric source; do not physically join role/skill/geographic rollups. Single-choice Scope and Role parameters select one precomputed alternative; a geography-view parameter chooses County/City/Community/County-only associations. Prepare SQL-approved results for the supported filter combinations or recompute from an appropriately permission-cleared detail source; disable unsupported filter combinations. Never sum distinct counts across overlapping cities, average medians, or average percentages with different denominators.

Acceptance requires actual Tableau-to-SQL checks for default, role, city-role, county, community, sparse and zero-result states. Multi-city selection is disabled; multi-location counting is verified with backend fixtures. Annual-field coverage and disabled arrangement/trend/pay comparisons remain visible. Counts must match exactly; percentages must match at documented display precision using the same rounding rule. Confirm denominator/coverage, minimum sample-size suppression and geographic scope; never claim native validation from Python/XML tests alone. Store the reconciliation evidence and document any unavailable views instead of substituting invented values.

### Tableau Public privacy and publication gate

Tableau Public is a public publishing destination, not private hosting. Published workbooks/data are publicly accessible, and publishing creates an extract. Use only source-authorized, publication-cleared CSVs and fields. Aggregation alone does not grant redistribution rights. Remove raw descriptions, contact information, credentials, source-native posting identifiers and unnecessary detail from publication exports. Inspect the entire workbook/extract, including hidden worksheets and unused fields, before upload; hiding a view or disabling downloads is not a confidentiality control.

If publication rights are unresolved, keep the workbook and permitted data local and mark the public link as blocked. Do not upload restricted data to obtain a portfolio URL. Screenshots, GitHub workbook files and packaged .twbx files also require review because packaging can include data. The [Tableau Public FAQ](https://help.tableau.com/current/pro/desktop/en-us/public_faq.htm) explains public visibility, download behavior and that CSV sources do not support automatic refresh. Plan a manual SQL export, local CSV refresh, recheck and authorized republication workflow; do not imply a live SQLite connection or automatic Public refresh.
